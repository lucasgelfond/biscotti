biscotti core and leaves

Today: 1,197 lines of agent TypeScript plus about 500 lines of VM and deploy scripts. The core can be about 800 lines; everything else becomes a leaf someone can swap, skip or write.

The opinion

  1. The core is an orchestrator: one conversation, memory, the task VM primitive with computer use, wakes, approvals, and the gate. Nothing in it knows about Google, Bitwarden, Exa or HTML pages.
  2. The gate is the extension point. Every tool a leaf adds, and every key it needs, goes through it with a policy: allowed, needs your yes, or blocked. That's what makes running other people's plugins safe.
  3. Leaves are just pi packages, MCP servers and skills. biscotti is built on pi, so pi packages work as they are; Hermes and OpenClaw skills (instructions plus CLIs) and any MCP server plug in behind the gate. Don't be prescriptive about which ship; let the installer pick a starter set.
  4. Executor becomes one leaf, kept for now for Google's OAuth. Long term, OAuth itself is a small leaf (sign-in, refresh, hand tokens to the gate), and Google and GitHub come from whichever plugins people like.
  5. The vault drops to a core secrets table, encrypted at rest, filled through a one-time form; Vaultwarden becomes an optional leaf for people who want a password manager.

The plugin shape

One config file lists what's installed: pi packages (tools and hooks), MCP servers (local or remote), and skills (instructions plus CLIs). Each entry declares the keys it needs and a policy per tool. The gate holds the keys and enforces the policies, and task VMs reach every leaf through it. The installer, or the setup web app, writes that file; adding a plugin later is one entry.
